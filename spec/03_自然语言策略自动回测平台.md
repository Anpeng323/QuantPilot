# Phase 3 · 模块3.1 自然语言策略自动回测平台 Spec

> 文档状态：已落地（后端+前端，AC3.1–AC3.5 全部通过）
> 关联：主文档 `SPEC.md`、Phase 1 规则回测引擎、Phase 2 Agent 编排
> 前置依赖：Phase 1（规则回测引擎，作为沙箱执行的目标 runtime）、Phase 2（策略分析 Agent 接入 `generate_backtest_from_nl`）

---

## 1. 目标与范围

### 1.1 目标
用户用**中文自然语言**描述策略（如「茅台站上60日线且RSI低于40时买入，跌破20日线卖出」），平台自动：LLM 生成回测代码 → **安全校验** → **受限沙箱执行** → 返回绩效与**可审阅代码**。这是平台差异化的重点能力。

### 1.2 In Scope
- NL → LLM 生成 Python 策略代码（基于 `indicators/registry` 与回测 runtime API）。
- **AST 白名单静态校验**（禁止危险语法/导入）。
- **受限沙箱执行**（禁系统/网络/文件、限资源与超时）。
- 可审阅代码展示（用户可见、可复制、可保存为策略记录）。
- 合规免责（生成结果仅为研究参考）。

### 1.3 Out of Scope
- 用户手写的任意 Python 直接执行（仅允许 LLM 在受限模板内生成）。
- 实盘/模拟盘资金（不做）。

## 2. 依赖与前置
- Phase 1 回测 runtime（提供 `run_backtest(params)` 或信号→绩效 API）。
- Phase 2 策略分析 Agent（工具 `generate_backtest_from_nl` 调用本流程）。

---

## 3. 详细业务规则

### 3.1 生成流程
1. NL 输入 → 组装 Prompt（含可用指标清单、`indicators/registry` 列名、示例模板）。
2. LLM 生成**仅含策略函数的 Python 代码**，必须返回 `signal: pd.Series(bool)` 或调用 `runtime.run_backtest(...)` 返回结果。
3. 代码进入 **AST 静态校验**。

### 3.2 AST 白名单静态校验（安全门禁，关键）
- 允许：函数定义、`import pandas/numpy`、`for/if/赋值`、调用 `indicators`、调用 `runtime.run_backtest`。
- 禁止（命中即拒）：`import os/sys/subprocess/socket`（及任何 `__import__`）、`eval/exec`、`open/file`、属性访问 `.__class__`/`__globals__`、`requests/urllib` 等网络、`subprocess`、`breakpoint`。
- 校验失败 → 返回可修改建议（如「检测到不允许的导入，请仅使用 pandas/numpy 与指标函数」），**不执行**。

### 3.3 受限沙箱执行
- 独立进程 / 受限命名空间；**禁网络、禁文件系统写、禁子进程**。
- 资源上限：CPU 时间 10s、内存 512MB；超时强杀。
- 仅向代码暴露白名单符号（`pd`、`np`、`indicators`、`runtime`、输入数据）。
- 执行结果（绩效 JSON + 日志）回传；异常捕获为降级 Observation。

### 3.4 可审阅与可复用
- 前端展示生成的完整代码（只读 + 复制 + 「保存为策略」）。
- 保存后写入 `strategy_record`（代码哈希、NL 原文、绩效快照、创建时间），供历史查看。

---

## 4. 输入 / 输出
- 输入：`{ natural_language: "茅台站上60日线且RSI<40买入...", stock_code?, days? }`。
- 输出：
```
{
  "generated_code": "...",
  "ast_passed": true,
  "executed": true,
  "metrics": { total_return, sharpe, max_drawdown, ... },
  "trades": [...],
  "review_url": "/strategy/{id}",
  "disclaimer": true
}
```

---

## 5. 异常流程
- **AST 校验失败**：返回拒绝原因 + 修改建议，不进入执行。
- **沙箱超时/内存超限**：强杀，返回「策略执行超时（可能计算过重），请简化或缩小区间」。
- **LLM 生成非代码/语法错**：捕获 SyntaxError，返回「生成代码有误，请换种描述」并建议重写 NL。
- **数据不足**：同 Phase 1 缺失率规则，提示换区间。

---

## 6. UI 交互规则
- 输入框：自然语言策略描述（占位示例可点击填充）。
- 结果区：左「生成代码（可审阅）」、右「绩效卡片 + 权益曲线 + 买卖点」。
- 加载态：显示「正在生成代码 / 正在安全校验 / 正在沙箱执行」分步状态。
- 合规：结果区顶部强制免责条「AI 生成策略仅供研究参考，不构成投资建议」。

---

## 7. 验收标准
- AC3.1：给定明确 NL 策略，端到端返回绩效且买卖点与手算样本一致（防未来函数沿用 Phase 1）。
- AC3.2：前端可见生成的完整代码，复制后能本地复现相同绩效。
- AC3.3（安全）：向 LLM 诱导生成含 `import os`/`eval`/`open` 的代码，AST 校验拒绝执行且无文件系统/网络访问发生（沙箱日志佐证）。
- AC3.4（合规）：所有 NL 回测结果页均含免责声明且 `disclaimer=true`。
- AC3.5：超复杂策略在沙箱内超时，平台优雅降级提示而非卡死。

---

## 8. 风险
- 沙箱逃逸（最高）：应对——AST 白名单 + 进程级资源/网络限制 + 最小符号暴露；定期红队测试。
- LLM 生成低效/错误代码：应对——模板约束 + 示例 few-shot + 超时兜底。
- 同质化策略泛滥：应对——`strategy_record` 去重（代码哈希）提示已有相似。
