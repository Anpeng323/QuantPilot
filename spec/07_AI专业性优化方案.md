# spec/07 · AI 功能专业性优化方案

> 范围：全部 5 个 AI 功能（AI 分析 / RAG 知识库 / NL 回测 / 量化选股 / 智能问答 Agent）以"专业性"为主线的统一优化。
> 约束：**仅用 MiniMax-M3 / MiniMax-M3.1-Flash-Preview**，不引入付费模型或外部 rerank 服务；RAG rerank 仅用本地规则实现。
> 状态：方案已确认，进入实现。本文件同时是评审报告 + 分阶段改造清单。

## 二、核心优化特征

1. **模型路由真正接入**：深度任务→MiniMax-M3，轻量任务→Flash，RAG 长文→M3。改动只是把 `llm.chat(...)` 换成 `router.chat_for_task(task_type, ...)`，零新增选择逻辑。
2. **投研框架化 prompt**：固定分析维度 + 输出结构契约 + 数据来源标注规范。
3. **结构化输出协议**：analyzer / agent 除 Markdown 正文外，统一返回 `score / confidence / citations / sources / disclaimer`。向后兼容（有则渲染，无则忽略）。
4. **数值化评分与置信度**：由确定性规则（数据覆盖度 + 因子分歧度）推导 **0–1 置信度**，不额外调 LLM，满足 NFR（问答 p95≤15s）。
5. **来源标注**：结论可追溯到 doc_id / 数据表 / 行情口径；按 spec §6.5 在最外层统一注入免责声明。

---

## 三、技术约束

- 后端 FastAPI，LLM 统一走 `ai/client.py`（仅 MiniMax）。
- rerank 仅本地规则：`score = 1 - cosine_distance` 阈值（<0.6 丢弃）+ metadata boosting（doc_type 权重、publish_date 新鲜度、stock_code 命中）。**不引入 BGE-reranker 等大模型权重**（待体积评估后再议）。
- 不改变沙箱/合规/数据表核心结构；仅新增 `agent_session` 表与若干可选返回字段。
- 响应缓存 key = 模型 + 消息指纹 + task_type，TTL 默认 24h。

## 四、结构化输出协议（统一 schema）

```python
# ai/structured.py
AnalysisResult = {
    "response": str,            # Markdown 正文（现有）
    "analysis_type": str,
    "score": float | None,      # 0-100 专业评分（如估值/风险/综合）
    "confidence": float,        # 0-1，由数据覆盖度 + 因子分歧推导
    "citations": [              # 来源标注
        {"type": "doc" | "data", "ref": "doc_id/表名",
         "label": "可读来源", "date": str}
    ],
    "disclaimer": bool,         # 是否已附 §6.5
    "degraded": bool,
    "model": str, "tokens": int, "cost_cny": float,
}
```

Agent 在现有 `{answer, steps, sources, ...}` 上新增 `confidence` 与 `citations`，复用同一套前端渲染组件。

置信度推导约定（`compute_confidence`）：
- 基础 = 数据覆盖度：有 `finance_core` 快照(0.3) + 有 `factors_daily`(0.2) + 有 `stock_market_cap`(0.2) + 有研报/公告(0.3)。
- 分歧惩罚：`PE_TTM` 分位、`ROE` 行业离散度等高于阈值时按档扣减，最终 clamp [0.3, 0.99]。
- `degraded=True` 时置信度置 0.3。

## 五、分阶段改造清单

### 阶段 0 · 公共底座
- [ ] `ai/client.py`：`_call_live` 加 `timeout`（opennai client timeout=30）+ 指数退避重试（2 次，base 1.5s）；新增可选响应缓存（按模型+prompt hash，TTL 24h，可 `DISABLE_LLM_CACHE=1` 关闭）；`chat()` 包裹统一异常 → 返回 `{text:降级短文, degraded:True}` 而非抛错。
- [ ] `ai/router.py`：保留 `chat_for_task`；增加 `task_type` 常量导出（`TASK_FINANCIAL` 等）便于 analyzer 引用。
- [ ] `ai/prompts.py`：新增 `RESEARCH_FRAMEWORK`（投研框架约束：固定章节、必须引用数字、区分事实/推测、标注来源）、`DISCLAIMER_SEC65`（spec §6.5 原文）、`STRUCTURED_CONTRACT`（要求模型在正文末尾附 `## 评分与置信度` 小节，含 0-100 评分与依据）。
- [ ] `ai/structured.py`：新增 `AnalysisResult` 构造器、`compute_confidence(stock_code)`、`attach_disclaimer(text)`。
- [ ] 所有 analyzer：`llm.chat(...)` → `router.chat_for_task(<task_type>, ...)`。

### 阶段 1 · AI 分析专业化

## 六、风险与回归策略

- **向后兼容**：`ai_analysis` 新增列用 `ALTER TABLE ... ADD COLUMN`（默认 NULL）；返回体新增字段前端"有则渲染"。
- **路由零风险**：`chat_for_task` 内部即调 `llm.chat`，仅多一层模型选择，不改变调用语义。
- **缓存风险**：同输入同输出，仅省 token；提供 `DISABLE_LLM_CACHE` 开关便于回归时关闭比对。
- **不削弱安全**：沙箱/白名单/合规校验保持；compliance 改写是"更严格"而非放松。
- **回归**：复用 `python scripts/regression_check.py --api <url>`，新增断言覆盖本方案特征。
