## 1. 目标与范围

### 1.1 目标
- 锁定已落地的核心能力，建立**可重复的回归门禁**，保证后续每个 Phase 的改动不破坏既有功能。
- 优化盘后数据更新（渐进回填）的配额与稳定性，在不触发 Tushare 限流的前提下持续扩大数据覆盖（财务三表、产业链、研报）。
- 为 Phase 1–6 提供干净、可信、可回退的开发基线。

### 1.2 In Scope
- 回归门禁（冒烟/数据快照/可视化快照三层）。
- Git 标签与里程碑管理规范。
- `etl/daily_update` 渐进回填配额调优、失败重试、断点续传。
- 数据质量监控（缺失/异常值告警）。

### 1.3 Out of Scope
- 任何新业务功能（回测、Agent、NL 回测、建议生成均不在本 Phase）。
- 数据库结构变更（本 Phase 只读基线）。

## 3. 详细业务规则

### 3.1 回归门禁（scripts/regression_check.py）
三层校验，CI/本地均可跑：
1. **冒烟层**：Web 服务 `/api/health` 返回 200；`indicators/registry` 可枚举全部指标；`knowledge/qa.ask` 能返回非空字符串。
2. **数据层**：抽样 `raw_daily`/`daily_basic` 最近 N 日非空；`financials` 表指定股票三表（利润/资产/现金流）非空；RAG 向量库文档数与切片数在阈值内。
3. **可视化快照层**：对固定股票+指标组合（如 `000001`+`ma`/`macd`/`boll`）调用 `renderIndicatorChart` 等价数据路径，断言返回 series 非空且颜色/类型符合 v1.3 约定（含 candle 序列）。
- 任意一层失败 → 退出码非 0，阻断合并/部署。

### 3.2 标签与里程碑
- `v1.3-indicator-chart` 为不可变基线锚点；后续每个 Phase 完成打新标签（如 `v1.4-backtest`）。
- 不允许在基线标签上 amend；回退统一走 `git checkout <tag>` 或 `git revert`。

### 3.3 盘后渐进回填（etl/daily_update）
- 每日收盘后触发；按**配额分批**拉取财务三表/产业链/行业/个股研报，避免瞬时打满 Tushare 分钟级限流。
- 失败任务进入重试队列（指数退避，最多 3 次），仍失败记入 `etl_failure_log` 并告警，次日续传（不重拉已完成）。
- 单股票财务数据更新频率：财报季日更，非财报季周更。

### 3.4 数据质量监控
- 行情缺口检测：相邻交易日缺失 > 阈值触发告警。
- 财务异常值（负值营收、资产负债率 > 100% 等）标记 `data_flag`，不阻断但前端黄色提示。

## 4. UI / 接口规则
- 无新增页面；复用现有「数据更新」状态展示（若有）。
- 回归门禁结果为 CLI 输出 + 可选落盘 JSON 报告。

---

## 5. 验收标准
- AC0.1：执行 `scripts/regression_check.py`，三层全部通过，退出码 0。
- AC0.2：人为注入一处数据缺失（删某股票近 1 日 `raw_daily`）后复跑，数据层报错且退出码非 0。
- AC0.3：`git checkout v1.3-indicator-chart` 后服务可正常启动并渲染 K线指标图。
- AC0.4：盘后跑 `etl/daily_update` 全程 0 次 Tushare 限流（429）报错，失败项进重试队列且次日续传成功。

---

## 6. 风险
- **Tushare 配额波动**：应对——配额分批 + 退避重试 + 非高峰调度。
- **基线无意被改**：应对——保护分支 + 回归门禁 + 标签不可变。
- **可视化快照脆弱**：应对——快照断言只校验 series 结构/类型/关键颜色，不绑定像素。
