## 2. 业务背景、目标与范围

### 2.1 业务背景：个人投研痛点
- **数据分散**：行情在行情软件、研报是 PDF、公告在交易所网站、宏观在统计局/央行，缺乏统一入口。
- **分析割裂**：看 K线、读财报、查公告、算指标、写复盘是割裂动作，无法串联。
- **自媒体生产慢**：财经创作者需把投研结论快速转为文稿/图表，重复劳动多。
- **AI 能力缺位**：现有工具重展示、轻推理；难以"问一只股票的风险点""对比两家公司毛利率"。
- **策略验证门槛高**：写回测代码需要编程能力，个人用户难以把"想法"快速变成可验证的回测。
- **成本敏感**：个人开发者无预算采购昂贵数据/算力，需尽量使用免费数据源与本地推理。

### 2.2 业务目标
**业务指标（BM）**
- 覆盖 A股全市场 ≥ 5300 只标的的行情与市值快照。
- 财报/研报/公告/资讯**自动爬取入库率 ≥ 95%**，盘后任务成功率 ≥ 99%。
- AI 分析调用成功率 ≥ 98%，RAG 召回 top-5 相关率 ≥ 85%。
- 单标的回测耗时 ≤ 10s（日级，规则回测）；自然语言回测代码生成 ≤ 30s，沙箱执行 ≤ 30s。
- AI 问答端到端 p95 ≤ 15s。
- 投资建议生成覆盖率：对有财务/行情数据的标的，可生成研究观点。

**产品价值**
- 投研闭环：数据→指标→RAG→分析→回测→报告一站式。
- **想法即回测**：自然语言描述策略 → 自动生成代码 → 沙箱回测 → 绩效，降低量化门槛。
- 可复用：提示词模板、策略、笔记、看板均可沉淀。
- 内容生产：自媒体文稿/PDF 一键生成，引用可追溯，且可带 AI 投资建议。

### 2.3 产品用户角色
| 角色 | 画像 | 核心诉求 |
|---|---|---|
| 个人深度投研用户 | 个人投资者/量化爱好者 | 看盘复盘、基本面分析、指标计算、策略回测（含 NL 自然语言回测）、RAG 查财报/公告、风险预警、**获取 AI 投资建议** |
| 财经自媒体创作者 | 财经博主/内容生产者 | 把投研结论（含 AI 建议）转为结构化文稿、嵌入图表、导出 PDF/Markdown 发布 |

### 2.4 In Scope（本次版本范围）
6 大模块全部纳入（详见 §5）：
1. 行情&基本面数据中心
2. 财报/公告 RAG 知识库（**自动爬取，无用户上传**）
3. 量化策略回测引擎（**含自然语言策略自动回测平台**）
4. AI 投研智能问答 Agent（不含报告撰写 Agent）
5. 可视化复盘与图表模块
6. 报告生成模块（自媒体投研文稿、复盘 PDF，可含 AI 投资建议）

### 2.5 Out of Scope（明确不做，规避范围膨胀）
- ❌ **禁止实盘自动下单 / 程序化交易 / 接入券商通道**；本平台只做研究、回测与建议，不下单、不托管资金、不开户。
- ✅ **允许 AI 生成投研观点与建议**（如估值判断、关注/回避建议、策略信号解读、目标价区间），但须标注"AI 观点，仅供参考"并附免责声明，**不得宣称确定性收益或保本**。
- ❌ 不做杠杆、融资融券、期权期货等衍生品交易执行。
- ❌ 不支持海外股票、港股（除特别规划外）、加密货币、外汇。
- ❌ 不做社交/跟单/社区分发（个人单机工作台定位）。

## 3. 用户故事

### 3.1 个人深度投研用户
- US-1：作为深度投研用户，我希望系统自动抓取到某公司年报/研报并直接问答，以便快速定位风险因素与关键科目，而不必手动上传 PDF。
- US-2：作为投研用户，我希望在 K线图上叠加 MA/BOLL 等指标并用不同颜色区分，以便一眼看清多空与支撑压力。
- US-3：作为投研用户，我希望输入"对比 600519 与 000858 的毛利率和 ROE"，以便横向评估两家白酒公司基本面。
- US-4：作为投研用户，我希望一键跑某策略的历史回测并看到收益/回撤/夏普，以便验证想法。
- US-5：作为投研用户，我希望用大白话描述一个策略（如"站上 60 日线且 ROE>15% 买入"），系统自动生成回测代码并跑出结果，以便我不会写代码也能验证。
- US-6：作为投研用户，我希望把某股票加入自选池并设置"跌破净资产"预警，以便被动监控。
- US-7：作为投研用户，我希望某股票出现减持/诉讼/质押公告时收到提示，以便及时识别雷点。
- US-8：作为投研用户，我希望问"这家公司最近宏观环境对它有什么影响"，以便结合 CPI/PMI/LPR 做判断。
- US-9：作为投研用户，我希望平台给出该股票的研究观点与建议关注（如估值偏高/性价比凸显），以便辅助决策。

### 3.2 财经自媒体创作者
- US-10：作为创作者，我希望基于某标的的财务+风险+估值分析（含 AI 建议），一键生成投研文稿（含图表），以便发文。
- US-11：作为创作者，我希望报告尾部自动带免责声明与数据来源，以便合规发布。
- US-12：作为创作者，我希望把多只股票对比结论导出为 Markdown/PDF，以便做"行业横向对比"专题。
- US-13：作为创作者，我希望引用可追溯到具体公告/研报原文，以便增强内容可信度。

## 4. 整体产品架构与业务流程

### 4.1 平台整体模块架构（文字描述）
```
┌──────────────────────────────────────────────────────────────┐
│  前端（原生 JS + ECharts + Markdown 渲染）                      │
│  自选池 · 行情图表 · RAG问答 · Agent对话 · NL回测 · 报告导出      │
└───────────────┬──────────────────────────┬───────────────────┘
                │ HTTP/JSON (FastAPI)        │
   ┌────────────▼──────────┐    ┌────────────▼──────────┐
   │ AI 投研问答 / Agent     │    │ 量化回测引擎            │
   │ (ReAct 编排 + 分析器)   │    │ (规则回测 + NL代码沙箱)  │
   └────────────┬──────────┘    └────────────┬──────────┘
                │ 工具调用                     │
   ┌────────────▼──────────┐    ┌────────────▼──────────┐
   │ RAG 知识库              │    │ 行情&基本面数据中心      │
   │ (Chroma 向量 + 分片)    │    │ (DuckDB 行情/财务/宏观)  │
   └────────────┬──────────┘    └────────────┬──────────┘
                │                             │
   ┌────────────▼─────────────────────────────▼──────────┐
   │ 系统基础能力：LLM 路由 · 调度(launchd) · 导出 · 记忆     │
   │ 数据源：自动爬取(adata/akshare/Tushare/公告/研报/资讯)    │
   └───────────────────────────────────────────────────────┘
```
- **存储分层**：DuckDB（结构化行情/财务）、Chroma（文档向量）、文件系统（原始研报/公告 PDF + 导出报告）、`doc` 表（文档元数据统一）。
- **调度**：macOS `launchd` 每日盘后（约 17:00）跑 `etl/daily_update`，含渐进回填配额。
- **爬取取代上传**：研报/公告/资讯/财报三表均由数据层**自动爬取入库**，用户不再手动上传文档。

### 4.2 用户端完整主流程
1. **数据自动接入**：盘后自动爬取行情/市值/财务/宏观/公告/研报/资讯（无需用户上传）；用户亦可导入 CSV 交易记录。
2. **指标计算**：对 K线实时计算 MA/MACD/BOLL/RSI/KDJ/ADX/ARBR/StochRSI（参数可配）。
3. **文档自动入库 RAG**：自动爬取的研报/年报/公告/资讯 → 分片 → BGE 本地 Embedding → Chroma；扫描件研报走 OCR。
4. **AI 投研问答**：单轮 RAG 问答，或多轮 Agent 编排（检索+工具调用），可输出**投资建议**。
5. **自然语言策略回测**：用自然语言描述策略（如"茅台站上 60 日均线且 ROE>15% 买入"），大模型生成回测代码并在沙箱执行，输出绩效与图表。
6. **生成复盘报告**：汇总分析结论（含 AI 投资建议）、嵌入图表、附引用与免责声明，导出 MD/PDF/Excel。

### 4.3 Agent 工作流（ReAct）
**触发逻辑**：当用户自然语言指令含分析/对比/复盘/日报/风险扫描/自然语言回测等意图，或显式选择"Agent 模式"时，进入 ReAct 编排器；普通单轮问答走 RAG 直答（不触发 Agent）。

**ReAct 循环**：
1. **Thought**：解析意图、拆解子任务、决定调用哪个工具。
2. **Action**：调用工具（见下），传入结构化参数。
3. **Observation**：拿到工具返回，判断是否满足或需继续。
4. 循环至产出最终答案或到达最大步数（默认 8 步）后强制汇总。

**工具调用规则**：
- 每次仅调用一个工具，参数须为 JSON；非法参数返回错误并自我纠正。
- 工具结果进入上下文，不泄露原始大表（截断/聚合后回传）。
- 涉及"价格/行情/财务"必须走工具查询，禁止大模型凭记忆编造数字。
- 涉及"文档内容"必须走 RAG 检索，返回须带 `doc_id`/`chunk_id`/`page` 溯源。
- 涉及"生成回测代码"须在**沙箱**执行：禁止访问文件系统（除只读 `data/`）、禁止网络、禁止任意导入；超时即终止。

**Agent 分工（3 个，不含报告撰写 Agent）**：
| Agent | 职责 | 主要工具 |
|---|---|---|
| 数据查询 Agent | 行情、财务、宏观、行业、公告的取数与聚合 | `get_quote` / `get_financials` / `get_macro` / `get_industry` / `get_announcements` |
| 财报解析 Agent | **自动检索/爬取** 财报与研报并提取科目、风险、亮点（无需上传） | `rag_retrieve` / `crawl_and_extract` |
| 策略分析 Agent | 指标计算、策略回测、**自然语言策略生成与自动回测**、绩效归因、投资建议生成 | `run_indicator` / `run_backtest` / `generate_backtest_from_nl` / `compare_stocks` / `suggest_investment` |

> 报告生成（模块6）作为**直接能力/工具**（`generate_report`）提供，不单独设 Agent；由用户或策略分析 Agent 调用，不进入多 Agent 编排链。

**RAG 与 Agent 的边界（强制）**：
- **RAG** 只负责"文档检索与片段召回"（自动爬取的财报/公告/研报/资讯），输出带引用的原文片段。
- **Agent** 负责"工具调用与任务编排"（查行情、跑回测、算指标、生成建议），可调用 RAG 作为一个工具，但不替代 RAG。

## 5. 分模块详细需求规格（核心）

> 每个模块含：功能描述、输入/输出、详细业务规则、UI 交互规则、正向流程、异常流程。
> 「实现状态」标注当前代码基线对齐情况（✅ 已落地 / 🟡 部分 / ❌ 规划）。

### 模块1 · 行情&基本面数据中心
**功能描述**：统一接入并存储 A股行情、市值估值、财务、宏观、行业产业链，提供自选池与预警。

**输入**：交易所/数据源（adata/akshare/Tushare）自动拉取；用户导入 CSV 交易记录。
**输出**：`daily_kline`/`minute_kline`/`stock_market_cap`/`finance_core`/`finance_statement`/`macro_indicator`/`industry_chain` 等表；行情/财务查询 API。

**详细业务规则**：
- 行情：A股日 K、周 K（`weekly_kline` 聚合）、5 分钟 K；复权价存储，展示默认前复权。
- 涨跌停：主板 ±10%、创业板/科创板 ±20%、ST ±5%；提示但不阻断分析。
- 市值快照 `stock_market_cap`：每日盘后刷新总市值/流通市值/现价/**PE/PB**（覆盖全市场 ≥ 5300 只）。
- 估值字段：`finance_core` 仅更新最新报告期行回填 pe/pb；缺失 ROE 由 `PB/PE×100` 推导；`finance_core` 当前仅覆盖 40 只（4461 行=40 只×多期），PE/PB 主供数以全市场快照为准。
- 财务：`finance_core`（核心指标聚合）、`finance_statement`（三表明细长表，东方财富口径免 token），盘后**渐进回填**（每夜配额，避免大批量超时）。
- 宏观：`macro_indicator`（CPI/PMI/LPR 等）按指标+日期主键。
- 行业/产业链：`stock_industry`（申万行业）、`industry_chain`（股票↔板块关系边）+ `industry_chain_meta`（板块进度）；东财行业 496 + 概念 506 板块，成分接口约 6s/板块，故**渐进填充**（每夜配额）。
- 去重：行情按 `(stock_code, trade_date, k_type)` 主键；文档按 `doc_id`（url hash）去重。

**UI 交互规则**：
- 行情页：蜡烛图（红涨白跌）+ 指标叠加 + `dataZoom` 缩放；加载态骨架；无数据空态提示"请先运行盘后回填"。
- 筛选：按行业/概念/自选池/代码搜索；列表分页（默认 50/页）。
- 财务页：报告期下拉、同比/环比标注、缺失值显示"-"而非报错。

**正向流程**：用户打开标的 → 拉取/读取 K线 → 叠加指标 → 查看财务卡片 → 加入自选。
**异常流程**：行情缺口 → 提示"数据至 YYYY-MM-DD，盘后补齐中"；财务缺失 → 显示"-"并提示回退快照估值；回填失败 → 重试并记日志，不影响已存数据。

**实现状态**：✅ 行情/市值/财务/宏观/行业/产业链已落地；🟡 周 K/研究卡片看板部分。

### 模块2 · 财报/公告 RAG 知识库（自动爬取，无用户上传）
**功能描述**：**自动爬取**并入库 研报/年报/公告/资讯，向量化检索与问答，支持引用溯源与多标的对比问答。**移除用户上传入口**，全部由数据层自动获取。

**输入（均为自动爬取）**：
- 研报：`akshare.stock_research_report_em`（按股票/行业，含评级/机构/盈利预测）。
- 公告：`data_ingest/announcement.py`（东财/交易所公开接口，按交易日）。
- 资讯：`data_ingest/news.py`（主财经新闻 + 个股，去重去噪）。
- 财报三表：`data_ingest/finance_statements.py`（东方财富口径，渐进回填）。
- 宏观：`data_ingest/macro.py`（CPI/PMI/LPR 等）。
- `doc` 表元数据（`doc_type`、`stock_code`、`title`、`url`、`publish_date`）。

**输出**：切片入库 Chroma；RAG 问答（答案+引用）；对比问答；财报解析 Agent 检索源。

**详细业务规则**：
- **自动爬取调度**：盘后任务 + 按需增量；研报按股票/行业订阅，公告按交易日全量增量，资讯按主财经+个股。爬取失败跳过并告警，不阻断其他源。
- 去重：按 `doc_id`（url hash）幂等；资讯额外按归一化标题去重、剔除广告词。
- 分片 `chunker`：按段落/标题切分，控制单片 token；保留 `page`/`section` 元数据。
- Embedding：BGE 本地模型（`embedder`），无联网；入库失败重试 3 次。
- 文档类型：`report`(研报/年报) / `announcement`(公告) / `news`(资讯) / `note`(笔记) / `research`。
- 检索 `vector_store.query`：支持 `stock_code` 单只、`stock_codes` 多只、`doc_types` 多类型（`$in` 过滤）。
- OCR：`loader` 对自动爬取的**无文本层扫描件研报**自动走 `rapidocr-onnxruntime` 本地识别。
- 对比问答 `rag_chain.compare`：结构化财务对比表 + 多股研报/公告检索 → LLM 横向对比。
- 引用溯源：回答须返回 `chunk_id`/`doc_id`/`page`/`text_preview`，前端展示可点击溯源。
- 财报解析 Agent 工具 `crawl_and_extract`：针对某标的自动检索其最新财报/研报并提取科目、风险、亮点，无需用户上传。

**UI 交互规则**：
- **移除上传区**；改为"数据源状态 / 爬取进度"面板（各源最近一次成功时间、库存量、失败告警）。
- 文档列表：按类型/标的/日期筛选、分页；显示切片数、来源与原文链接。
- 问答框：流式输出；引用以角标 `[doc_id=xxx]` 展示，点击展开原文片段。
- 空库态：提示"正在自动爬取，请稍候或查看爬取进度"（首次部署时）。

**正向流程**：盘后自动爬取 → 解析/分片 → Embedding → 入库 → 用户问答（带引用，无需任何上传动作）。
**异常流程**：
- 某源爬取失败 → 跳过该源、记录告警、其他源正常；面板标注"研报源 09-13 失败"。
- 扫描件 OCR 失败 → 提示"该研报无文本层且 OCR 失败，已跳过"，不阻断其他文档。
- Embedding 异常 → 重试 3 次后退化为"仅元数据入库，检索不可用"并告警。
- 空库问答 → 返回"知识库暂无可检索内容，正在自动爬取"引导文案，不调 LLM。

**实现状态**：✅ RAG 链路/对比问答/OCR 已落地；🟡 研报/公告/资讯自动爬取已落地，全市场覆盖随渐进回填推进。

### 模块3 · 量化策略回测引擎（含自然语言自动回测平台）
**功能描述**：让用户以指标信号定义策略并在历史数据回测；并新增**自然语言策略自动回测平台（重点）**：用大白话描述策略，大模型生成回测代码并在受限沙箱执行，降低量化门槛。

**输入**：
- 规则模式：股票池（单只/组合/行业）、信号规则（可视化/JSON）、回测区间、初始资金、成本参数。
- **NL 模式**：自然语言策略描述（如"贵州茅台站上 60 日均线且 ROE>15% 时买入，跌破 20 日均线卖出"）。

**输出**：权益曲线、交易记录、绩效指标（收益率/年化/夏普/最大回撤/胜率）、基准对比（沪深300）；NL 模式另输出**生成的回测代码**（可审阅/编辑后重跑）。

**详细业务规则（规则回测）**：
- 数据：日级回测基于 `daily_kline`（前复权）；信号可引用任意 `indicators` 输出。
- 撮合：信号日收盘判定，次交易日开盘或收盘成交（可配）；不允许未来函数。
- 成本模型：印花税 0.05% 单边 + 佣金 0.025%（最低 5 元）+ 过户费 0.001%；可选滑点（默认 0）。
- 持仓：支持满仓/固定仓位/按信号权重；不允许卖空（A股现货）。
- 绩效：总收益、年化（交易日 252）、夏普（无风险利率默认 2%）、最大回撤、胜率、基准（沪深300 `index_kline`）超额收益。
- 任务管理：`backtest_task`（状态/参数/结果摘要）、`strategy_record`（可复用策略）。

#### 3.1 自然语言策略自动回测平台（重点新增）
- **触发**：用户在"NL 回测"输入框描述策略（支持条件组合：均线/指标交叉、估值过滤 ROE/PE、持仓周期、止损止盈等）。
- **生成**：LLM 将 NL 转为结构化策略 DSL / Python 代码，约束使用白名单库（`pandas`/`numpy`/`indicators`/内置回测框架 API），**禁止** `import os/sys/requests/subprocess` 等。
- **静态检查**：生成代码先经 AST 白名单校验（仅允许指定导入与 API），拒绝越权调用；不通过则返回"请简化策略描述"。
- **沙箱执行**：在受限环境运行——禁用文件系统写（除临时结果）、禁用网络、禁用任意导入；超时（默认 30s）即终止并捕获异常。
- **产物**：回测结果（收益/回撤/夏普/交易列表）+ 可执行代码（用户可微调后重跑）；代码与结果一并存入 `backtest_task`。
- **Agent 接入**：策略分析 Agent 可通过 `generate_backtest_from_nl` 工具调用本能力，串联"描述→生成→执行→解读"。
- **投资建议**：回测结果可经 `suggest_investment` 生成研究观点（如"该策略历史夏普 1.2，可考虑关注"，仍须附免责声明）。

**UI 交互规则**：
- 规则模式：策略编辑器（指标信号可视化拼接或 JSON）+ 参数面板（区间/资金/成本）。
- NL 模式：自然语言输入框 + 生成代码预览（可编辑）+ 运行/重跑按钮 + 结果图表（权益曲线/回撤/交易表）。
- 加载态："生成回测代码中…"/"沙箱回测中…"；空态提示"暂无回测任务"。
- 导出：MD/PDF/Excel（含代码与绩效）。

**正向流程（规则）**：选股 → 设信号 → 设成本 → 运行 → 看绩效 → 保存/导出。
**正向流程（NL）**：描述策略 → LLM 生成代码 → 静态检查 → 沙箱执行 → 展示绩效 + 代码（可编辑重跑）。
**异常流程**：
- 规则模式：参数非法（区间颠倒/资金≤0）→ 前端校验 + 明确文案，阻断提交；数据不足（标的上市晚于区间）→ 提示"该标的在区间内数据不足 N 日"；计算溢出/NaN → 捕获并提示"回测计算异常，请检查信号定义"。
- NL 模式：描述无法解析 → 返回可编辑模板引导改写；代码执行越权/超时 → 终止并提示"策略过于复杂，请简化或改用规则模式"；静态检查拒绝 → 提示"生成的代码使用了受限操作，已拦截"。

**实现状态**：🟡 指标计算（`indicators`）已落地；规则回测引擎为规划项；**自然语言自动回测平台为规划重点项**（需 LLM 代码生成 + 沙箱执行 + AST 白名单）。

### 模块4 · AI 投研智能问答 Agent
**功能描述**：基于大模型+RAG+工具调用的投研问答，覆盖财报解读、估值、风险、行业、宏观、对比，**并可生成 AI 投资建议**。

**输入**：用户自然语言问题 + 可选 `stock_code`/`stock_codes`；Agent 模式标记。
**输出**：结构化回答 + 引用溯源 + 强制免责声明 + （如适用）**投资建议**；多轮可追问。

**详细业务规则**：
- 模型路由 `ai/router.py`：按 `task_type` 选模——深度分析走 Qwen-Max/MiniMax-M3，轻量/校验走 Qwen-Plus/Flash，长文 RAG 走 Qwen-Long；支持 DeepSeek 推理、Mock 测试。
- 分析器（已落地，`ai/analyzers/`）：`financial`(财报解读) / `valuation`(估值) / `dcf`(DCF) / `profit`(盈利拆解) / `risk`(风险扫描) / `sentiment`(情绪) / `industry`(行业景气) / `macro`(宏观) / `comparative`(横向对比)。
- RAG 边界：文档类问题必须 `rag_retrieve`（检索**自动爬取**的财报/研报/公告），返回带引用；禁止无依据编造数字。
- 投资建议：当用户询问"是否值得关注/估值如何/后续怎么看"时，可由 `suggest_investment` 生成研究观点，须标注"AI 观点，仅供参考"，**不得宣称确定性收益或保本**。
- 免责声明：所有 AI 文本输出末尾强制追加 §6.5 标准文案（不可被用户关闭）。
- 降级：缺财务数据 → 提示"暂无该标的财务，已用市值快照估值"而非报错；LLM 超时 → 返回降级短文 + 重试建议。

**UI 交互规则**：
- 对话区：问题输入、流式回答、引用角标可展开；加载态"AI 思考中…"；错误态明确文案。
- 标的绑定：输入关联股票代码时自动带入上下文；多标的对比显式列表。
- 建议高亮：投资建议以独立卡片展示并标注"AI 观点，仅供参考"，与事实陈述区分。
- 历史：会话可保存/清空；`/memory` 记忆用户偏好（如"偏价值投资"），分析时贴合。

**正向流程**：输入问题 → 路由/检索 → 调用分析器或 Agent 编排（可含 `generate_backtest_from_nl`/`suggest_investment`）→ 生成带引用回答 + 免责声明。
**异常流程**：见 §9（LLM 超时、限流、RAG 空库、工具参数非法、NL 回测代码越权等）。

**实现状态**：✅ 单轮 RAG 问答 + 多分析器已落地；🟡 Agent ReAct 编排与 NL 回测/投资建议为规划项（Phase E）。

## 6. 数据模型与数据源设计

### 6.1 外部数据源
| 数据源 | 用途 | 备注 |
|---|---|---|
| adata | 行情/财务核心/行业（免费、免 token） | 主用 |
| akshare | 宏观(CPI/PMI/LPR)、新闻、公告、**研报自动爬取**、板块成分 | 主用 |
| Tushare | 更深财务三表/高频（需 token） | 可选升级，env 注入 |
| akshare 研报/公告 | **研报/公告自动爬取（取代用户上传）** | `stock_research_report_em`/`announcement`，文件系存原文 + Chroma |
| 上市公司公告 | 交易所公开接口（东财/cninfo） | 控频合规 |
| 自定义 CSV | 个人交易记录导入 | 文件上传（仅用户自身交易，非研报/财报） |

### 6.2 核心实体与字段定义（摘选）
- **stock_basic**：`stock_code, short_name, exchange, industry, list_date, is_st` 等。
- **daily_kline / minute_kline**：`stock_code, trade_date/trade_time, open, high, low, close, volume, amount, change_pct, k_type`。
- **stock_market_cap**：`stock_code, trade_date, total_market_cap, float_market_cap, price, pe, pb`（PE/PB 全市场快照）。
- **finance_core**：`stock_code, report_date, eps, roe, gross_margin, revenue, net_profit, yoy_rev, yoy_pft, pe, pb, total_market_cap`（仅 40 只，多报告期）。
- **finance_statement**：三表明细长表（`stock_code, report_date, statement_type, item, value`）。
- **macro_indicator**：`indicator, trade_date, value, unit`（cpi/pmi/lpr_1y/lpr_5y/m2…）。
- **stock_industry**：`stock_code, industry_sw`（申万行业）。
- **industry_chain / industry_chain_meta**：股票↔板块关系边 / 板块抓取进度。
- **doc**：`doc_id, doc_type, source, stock_code, title, publish_date, url, chunk_count, metadata`（RAG/公告/资讯/研报统一，均自动爬取）。
- **note / watchlist* / alert_* / portfolio* / ai_analysis / prompt_template / memory**：笔记/自选/预警/持仓/分析/提示词/记忆。
- **backtest_task / strategy_record**：回测任务（含 NL 生成代码与结果）/ 可复用策略。

### 6.3 数据更新策略与生命周期
- **盘后调度**：`launchd` 每日 ~17:00 跑 `etl/daily_update`（行情/市值/财务/宏观/公告/**研报/资讯自动爬取**/产业链渐进回填）。
- **渐进回填**：三表/产业链/研报按每夜配额（如 50 只/30 板块）逐步铺满，避免超时与限流。
- **生命周期**：行情/财务长期保留；`doc` 原文与向量长期保留；日志滚动 30 天；`backtest_task` 结果保留可配置。
- **去重**：行情按主键 upsert；文档按 `doc_id`（url md5）幂等。

### 6.4 数据存储方案
- **DuckDB**：结构化行情/财务/宏观（单文件 `data/quant.duckdb`）。
- **Chroma**：文档向量（`data/chroma/`，随代码/可重建）。
- **文件系统**：原始研报/公告 PDF + 导出报告（`data/`、`exports/`）。
- **git 基线**：`data/*.duckdb` 已 gitignore，仅存结构与基线 tag。

### 6.5 金融合规要求（重点）
- **强制免责声明**：所有 AI 生成文本（问答、分析、报告、Agent 输出、投资建议）末尾须含：
  > 「以下为 AI 基于公开数据生成的**研究观点与建议**，仅供个人学习参考；**不构成对任何证券的确定性判断或收益保证**，投资决策需独立判断并自担风险。市场有风险，投资需谨慎。」
- 页面 footer、报告尾部固定展示，用户不可关闭。
- **投资建议合规**：允许给出投研观点/建议关注/估值区间/策略信号解读，但须明确标注"AI 观点，仅供参考"，**不得宣称保本、确定性收益或诱导集中持仓**；涉及具体标的时须回链数据与来源。
- **数据来源标注**：引用须标 `doc_id`/来源与日期；宏观/行情标注口径（如"东方财富口径"）。
- **代码安全（NL 回测）**：自然语言生成的回测代码仅在受限沙箱执行（禁用文件系统写/网络/任意导入），超时即终止，禁止越权；生成代码先经 AST 白名单静态检查。
- **隐私**：单用户本地部署，不上传个人持仓/笔记至第三方；API Key 仅存环境变量。

## 7. 外部依赖与接口规格

### 7.1 大模型依赖
- **主推 Qwen 系列**（通义千问）：Qwen-Max（深度分析）、Qwen-Plus（通用）、Qwen-Long（长文 RAG 上下文）。
- 备选：MiniMax-M3/M3.1-Flash、DeepSeek（推理）、Mock（测试）。
- 接口：OpenAI 兼容 `/v1/chat/completions`；经 `ai/client.py` 统一封装，`ai/router.py` 按 `task_type` 路由。
- Agent 框架：可基于 **LangGraph** 或 **Qwen-Agent** 构建 ReAct 编排，亦可自研轻量 ReAct 循环（当前规划）。
- **NL 回测代码生成**：使用代码能力强模型（Qwen-Max / DeepSeek-Coder 类），输出受 AST 白名单约束。

### 7.2 向量数据库依赖
- **Chroma**（本地优先，零运维）；可平滑切换 Milvus（大规模时）。
- Embedding：BGE 本地模型（无联网、免费）。

### 7.3 数据 API 依赖
- **Tushare**：`pro` 接口，需 `TUSHARE_TOKEN`（env）；限频（积分制）。
- **adata / akshare**：免费、免 token；akshare 注意反爬与接口变动；研报/公告/资讯经 akshare 自动爬取。
- 字段映射：统一归一到内部 `stock_code`（6 位）/ `trade_date`（ISO）。

### 7.4 超时 / 限流 / 重试
| 依赖 | 超时 | 重试 | 限流 |
|---|---|---|---|
| LLM 调用 | 60s（深度）/ 20s（轻量） | 2 次指数退避 | 按 key 配额，超则降级小模型 |
| Embedding | 30s/批 | 3 次 | 本地无限制 |
| 行情/财务 API | 30s | 3 次退避 | 尊重接口 QPS，夜间配额 |
| 公告/研报抓取 | 30s | 2 次 | 控频防封 |
| NL 回测代码生成 | 30s | 1 次（失败转引导） | 按 key 配额 |
| 沙箱执行 | 30s | 0（超时即终止） | 单任务串行 |

## 8. 非功能需求（NFR）
- **性能**：K线渲染 <1s；指标计算 <500ms/标的；规则回测 ≤10s（单标的日级）；NL 回测（生成+沙箱）≤60s；问答端到端 p95 ≤15s；RAG 召回 <500ms。
- **稳定性**：单用户本地进程；`launchd` 守护；`scripts/regression_check.py` 三层回归（数据/前端/API）保 MVP 不回退。
- **容量**：A股 ≥5300 只；行情数年；Chroma 文档万级；DuckDB 单文件 GB 级。
- **安全**：本地单用户、无公网暴露；API Key 环境变量；个人数据不出本机；NL 回测沙箱隔离。
- **兼容性**：macOS（主）/ Linux；现代浏览器（Chrome/Edge）；前端原生 JS + ECharts。
- **成本控制**：轻量任务走小模型；Embedding 本地免费；Tushare 仅在需深数据时用；`estimate_cost` 埋点监控。

## 9. 异常场景与错误处理
| 异常 | 错误提示文案（用户可见） | 降级策略 | 日志埋点 |
|---|---|---|---|
| 数据源拉取失败 | "行情/财务数据拉取失败，已保留已有数据，稍后自动重试" | 用本地已有数据；跳过该源继续其他 | `source=fail, name, err` |
| 研报/公告爬取失败 | "研报/公告自动爬取暂失败，已跳过，下次重试" | 跳过该源，面板告警 | `crawl_fail, source` |
| 扫描件 OCR 失败 | "该研报无文本层且 OCR 失败，已跳过" | 仅元数据入库，检索不可用 | `ocr_fail, path` |
| 大模型超时 | "AI 响应超时，已降级为简版结论，可重试" | 返回缓存/简版；建议重试 | `llm_timeout, model, task` |
| 向量入库失败 | "文档已保存但向量化失败，检索暂不可用" | 重试 3 次后告警 | `vec_ingest_err, doc_id` |
| 规则回测计算溢出 | "回测计算异常，请检查信号定义（如除零/空值）" | 终止该任务，保留参数 | `backtest_err, task_id` |
| 策略参数非法 | "参数不合法：区间/资金/信号需…" | 前端阻断提交 | `param_invalid, field` |
| 自然语言解析失败 | "未能将描述转为有效回测，请换种说法或改用规则模式" | 返回可编辑模板引导 | `nl_backtest_gen_err` |
| 回测代码沙箱越权/超时 | "回测执行超时或被安全策略拦截，请简化策略" | 终止执行，保留草稿 | `sandbox_block, task_id` |
| RAG 空库 | "知识库暂无可检索内容，正在自动爬取，请稍候" | 不调 LLM，给引导 | `rag_empty` |
| 行情缺口 | "数据至 YYYY-MM-DD，盘后补齐中" | 展示已存区间 | `data_gap, code` |

## 10. 埋点与观测指标
**业务指标（BM）**
- 文档自动入库数/日（研报/公告/资讯）、RAG 问答数/日、回测任务数/日（规则+NL）、NL 回测占比、报告生成数/日、投资建议生成数。
- 财务覆盖数、行业覆盖数、公告/资讯入库数、研报爬取覆盖率。

**技术指标（TM）**
- 接口 p95 延迟（行情/问答/回测/RAG/NL生成）。
- LLM 调用耗时、token、成本（按 task_type）；NL 回测代码生成耗时与沙箱执行耗时。
- RAG 召回 top-5 相关率（抽样评测）。
- 沙箱拦截率（越权/超时占比）。
- 回归脚本通过率、盘后任务成功率。

## 11. 验收标准（Acceptance Criteria）
**模块1 行情&基本面**
- AC1.1：打开任一 A股标的，蜡烛图正确渲染（阳红阴白），支持 MA/BOLL 叠加且颜色区分清晰。
- AC1.2：`stock_market_cap` 每日刷新，PE/PB 覆盖 ≥ 95% 全市场标的。
- AC1.3：缺失 `finance_core` 的标的，估值分析回退快照且不报错。

**模块2 RAG（自动爬取）**
- AC2.1：盘后任务运行后，系统自动入库研报/公告/资讯，用户无需上传即可问答并检索到相关内容且带 `doc_id/page` 引用。
- AC2.2：无文本层扫描件研报经 OCR 后可被检索到关键文本。
- AC2.3：`/rag/compare` 对两只股票返回横向对比且引用可追溯。
- AC2.4：前端无"上传文档"入口；提供数据源爬取状态面板。

**模块3 回测（含 NL）**
- AC3.1：规则模式给定"MA5 上穿 MA20"策略与区间，输出权益曲线、最大回撤、夏普，且与手写基准误差 <1%。
- AC3.2：成本模型计入印花税+佣金+过户费；非法参数被阻断并给文案。
- AC3.3（NL 重点）：输入"站上 60 日线且 ROE>15% 买入，跌破 20 日线卖出"，系统在 60s 内生成可执行回测代码并在沙箱跑出绩效；生成代码不含受限导入（AST 校验通过）。
- AC3.4（NL 安全）：若在生成代码中注入 `import os`/网络请求，静态检查/沙箱拦截并提示，不执行。

**模块4 Agent 问答（含建议）**
- AC4.1：问"解读 600519 财报风险"，返回含引用且带免责声明的结构化回答。
- AC4.2：所有 AI 文本输出末尾含 §6.5 标准免责声明（自动化断言）。
- AC4.3：问"这只是否值得关注"时返回标注"AI 观点，仅供参考"的研究建议，且不含保本/确定性收益宣称。
- AC4.4：缺数据时返回引导文案而非 500。

**模块5 可视化**
- AC5.1：指标切换后旧序列不残留（notMerge）；配色两两可区分（色盲友好校验）。
- AC5.2：无数据时显示明确空态，不白屏。

**模块6 报告**
- AC6.1：生成投研文稿含图表与引用，尾部强制免责声明。
- AC6.2：勾选"含 AI 投资建议"后，文稿出现标注"AI 观点，仅供参考"的建议章节，且不含保本/确定性收益宣称。

## 12. 上线策略、灰度、回滚方案
- **部署**：单用户本地（macOS/Linux），`python -m web.app` 或 `launchd` 守护。
- **灰度**：功能开关（feature flag）按模块逐步开放；先内部使用再对外演示；NL 回测先对白名单用户开放（代码安全未稳前）。
- **回滚**：`git tag` 基线（如 `mvp-v1`、`v1.3-indicator-chart`）；回退 `git checkout <tag>`；数据回滚备份 `data/quant.duckdb` 副本。
- **回归门禁**：每次变更跑 `scripts/regression_check.py`，不通过禁止合入主分支。

## 13. 风险评估与备选降级方案
| 风险 | 类型 | 应对预案 |
|---|---|---|
| 数据源断更/接口变动 | 业务/技术 | 多源冗余（adata+akshare+Tushare）；失败用本地数据降级；监控告警 |
| `finance_core` 覆盖仅 40 只 | 数据 | PE/PB 主用全市场快照；规划 `finance_adata` 全量回填 |
| Agent 幻觉/编造数字 | 技术/合规 | 强制工具取数 + RAG 引用；禁止无依据结论；输出校验 |
| LLM 成本超支 | 成本 | 轻量任务走小模型；本地 Embedding；`estimate_cost` 监控与上限 |
| 公告/研报爬取被反爬 | 合规/技术 | 控频、用公开接口、遵守 robots；失败跳过不影响主流程 |
| 合规风险（建议边界） | 合规 | 强制免责声明 + "AI 观点仅供参考"标注 + 禁止保本/确定性收益宣称 + 来源回链 |
| NL 回测代码安全 | 技术/安全 | 受限沙箱执行（禁文件系统写/网络/任意导入）+ 超时终止 + AST 白名单静态检查 |
| 回测未来函数 | 技术 | 撮合次交易日成交；信号校验禁止使用未来数据 |
