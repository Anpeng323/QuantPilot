1 · 项目概览

系统解决的核心问题：投研信息分散在行情软件、财报 PDF、券商研报、交易所公告里，研究员要在多个系统间来回切换，且结论难以复用和溯源。 本项目把它收敛成一个统一的、可被大模型驱动的工作台：

  • 数据底座：自动接入行情 / 财务 / 估值 / 因子 / 产业链 / 宏观 / 公告研报等多源数据，落地到统一存储层（关系库 MySQL + 向量库 Chroma），全市场口径统一。
  • AI 分析层（重点）：以 ReAct Agent 为核心，配合 13 个白名单工具、13 个专业分析器、一套本地 RAG 知识库，把“查数据 → 算指标 → 写报告 → 对话问答”串成可编排的工作流。
  • 服务层：FastAPI 暴露 REST / 流式接口，前端工作台调用，支持多轮追问、回测、选股、综合报告。

4 · 数据层与 ETL（AI 的“燃料”）

AI 结论的质量取决于数据覆盖度，因此数据层设计强调 多源冗余 + 渐进回填 + 单存储统一。

ETL 设计要点

  • 快速版 update_kline_fast.py：复用并发抓取（线程池 + 单只超时），每个任务独立 try/except，soft-fail 不互相阻断；支持 --only 选跑、--no-system-proxy 直连。
  • 渐进回填：财务/产业链等重任务每夜只新增固定配额（per_night），多夜铺满全市场，避免单夜超时。
  • 双源改造（路径 2，本项目的真实工程决策）：东财网络在本机受限，财务改用 ak.stock_financial_abstract（新浪）建独立新表 finance_abstract，不改动原有 finance_statement/finance_core，从而不破坏已有因子计算链路；市值暂无法替代则保持冻结态。

5 · AI 能力架构（重点）

AI 层是项目灵魂，由「一个 Agent 编排核心（大脑）」+「三层能力」组成：① 工具层（白名单，拿原始数据）② 分析器层（专家，出专业结论）③ 基础底座（模型路由 / 知识库 / 结构化等公共能力）。编排核心统一调度三层，三层再落到存储层与外部大模型。

为什么这样分层？

  • Agent 不直接写提示词调 LLM，而是经过 router 按任务类型选模型、经过 structured 统一做评分/引用/降级——能力可复用、可测试。
  • 工具与分析器解耦：Agent 通过工具拿“原始数据”，分析器面向“专业结论”；综合报告分析器会自行调用工具子集走一轮轻量 ReAct。
  • 合规与置信度是“横切”逻辑，在 Agent 出口与分析器出口统一生效，保证所有对外输出都带免责声明与可信度。

6 · LLM 接入与模型路由

统一客户端 ai/client.py

  • 多 Provider 抽象：基于 OpenAI 兼容接口，支持 MiniMax（主）、Qwen、DeepSeek、Mock，用环境变量 LLM_PROVIDER 切换。
  • 生产级韧性：响应缓存（模型+消息指纹，TTL 24h，省 token）、指数退避重试 ×2、空内容视为失败触发重试、最终失败降级返回（degraded=True，不抛 500）。
  • 质量处理：剥离模型 <think> 推理块、注入强制中文系统提示、进度回调（线程局部，供前端 SSE 推送）。
  • 成本可观测：estimate_cost 按模型单价估算每次调用花费（元）。

模型路由 ai/router.py

按 task_type 自动选模型，平衡效果与成本/时延：

任务类型路由模型理由
财报 / 估值 / DCF / 行业 / 综合 / 回测结论MiniMax-M3（深度）推理强、需长上下文
情绪 / 抽取 / 分类 / 摘要 / 预警分类MiniMax-M3.1-Flash快且便宜

7 · ReAct Agent 工作流（重点）

ai/agent/react.py 是系统的对话大脑。它实现了一个受约束的 ReAct（Reasoning + Acting）循环：LLM 输出 Thought + Action(JSON) → 执行白名单工具 → 回填 Observation → 下一轮，直至 final_answer 或达到最大步数（默认 6）。

flowchart TD
  A0[用户提问] --> A1{意图识别与分类}
  A1 -->|无标的 + 闲聊 / 能力咨询| CH[闲聊快速通道（单次回复）]
  A1 -->|投研意图 / 含股票| AG[投研 Agent 主流程]
  AG --> P1[预取真实行情快照（防幻觉）]
  P1 --> LOOP{{ReAct 推理循环（最多 6 步）}}
  LOOP --> L1[模型生成思考与动作]
  L1 --> L2{解析动作结果}
  L2 -->|final_answer| FA[生成最终答案]
  L2 -->|action| L3[白名单工具调用执行]
  L3 --> L4[观测结果回填上下文]
  L4 --> LOOP
  LOOP -->|步数耗尽未收敛| SYN[独立上下文强制合成]
  FA --> G1[结构化数据转自然语言]
  SYN --> G1
  G1 --> G2[合规改写与免责声明]
  G2 --> G3[置信度计算]
  G3 --> G4[生成追问建议]
  G4 --> OUT[返回答案与引用等结果]
  CH --> OUT

关键工程细节（强烈建议面试展开）

① 防幻觉：预取真实数据
进入推理前先调一次 get_quote 把真实行情喂给模型，并在系统提示里严禁凭记忆编造数字——每个具体数字必须来自工具 Observation。
② 强制取数护栏
若模型声称“数据拿不到”却一次工具都没调，或涉及个股却凭记忆作答，会主动回灌提示逼它先调真实工具；回测请求未跑则强制调用 run_backtest。
③ 抗“元信息回复”
识别并过滤“已切到严格 JSON 模式”这类复述格式的无意义回复，必要时用独立干净上下文重新合成，绝不让格式提示变成最终答案。
④ 结构化→人话
模型若把 JSON/键值对当答案，触发 _humanize 二次 LLM 改写或兜底摊平成中文要点，保证输出可读。
⑤ 多轮省略主语
“它风险呢？”这类追问，沿历史对话解析最近标的继续作答；寒暄走秒级直达通道，避免被 ReAct 的 JSON 约束带偏。
⑥ 确定性置信度
置信度由“已取数工具覆盖度”确定性推导（0.3–0.95），不额外消耗 LLM，可解释、可审计。
一句话总结 Agent 设计哲学：“LLM 只负责推理与表达，所有事实必须来自白名单工具返回的结构化 Observation；格式、幻觉、合规在出口统一兜住。”

置信度与引用（确定性，零额外 LLM 成本）

  • compute_confidence(stock_code)：按 finance_core / factors_daily / 市值 / 文档四类覆盖度加权推导 0.3–0.99，无数据取最低 0.3，避免虚高。
  • extract_score：从 LLM 输出“## 评分与置信度”正则抽取 0–100 综合评分。
  • build_data_citations：自动列出确实含该股票的表作为数据来源标注。
面试亮点：把“置信度/引用/评分”从 LLM 生成中解耦成确定性函数，既省 token 又保证可复现、可审计，是生产级 LLM 应用的常见降本增效手法。

10 · 综合报告生成器（轻量 ReAct + RAG + 溯源）

ai/analyzers/comprehensive.py 产出一份统一专业个股报告，本身也是一个受控的 ReAct 循环（6 步，工具白名单子集：行情/财务/研报/公告/行业/宏观/RAG/联网）。它最能体现“Agent + RAG + 可溯源”的工程结合：

flowchart TD
  S0[输入目标股票代码] --> S1[设定六章报告结构与引用规范]
  S1 --> LP{{ReAct 循环（最多 6 步）}}
  LP --> L1[模型决策：调工具或收口]
  L1 -->|action| L2[调用白名单工具子集]
  L2 --> L3[观测结果回填]
  L3 --> LP
  L1 -->|final_answer| R1[检查引用完整性]
  R1 -->|正文引用编号但缺定义| R2[缺引用时确定性重建来源清单]
  R1 -->|完整| R3[输出报告]
  R2 --> R3
  R3 --> R4[补齐参考资料章节]
  R4 --> OUT[保存分析与引用记录]
  • 引用溯源：从工具返回中确定性提取真实出处（研报名/公告标题/网页链接/财报期），按 [1][2][3] 编号，正文与参考资料一一对应，杜绝“编造引用”。
  • 嵌套调用规避：综合报告只放“纯取数”工具；会再触发 LLM 的 compare_stocks/suggest_investment 不纳入，避免超 15s 超时与递归。
  • 进度可观测：on_stage 回调向上层推送“准备/思考/调工具/渲染”进度，前端据此做 SSE 流式展示。

11 · RAG 知识库链路

knowledge/ 实现了完整 RAG 流水线：文档原文 + 向量 + 元数据统一存入专用向量库 Chroma（与关系库解耦）。

flowchart LR
  F[原始文档（PDF / 研报 / 公告）] --> LD[文档解析加载]
  LD --> CK[段落切片分块]
  CK --> EM[本地向量嵌入]
  EM --> VS[(Chroma 向量库)]
  Q[用户提问] --> EQ[问题向量化]
  EQ --> VQ[向量相似检索]
  VQ --> RR[本地重排与过滤]
  RR --> EN[补充文档元数据]
  EN --> P[拼接提示词]
  P --> LLM[模型生成带引用回答]
  LLM --> OUT[RAG 检索工具返回结果]
  • 本地 rerank：不接付费重排服务，用“相似度阈值过滤 + 文档类型 boosting（报告/公告权重更高）+ 标题词重叠加分”做轻量重排，降噪且零成本。
  • 可溯源：每个 chunk 带 doc_id / section / doc_type / stock_code 元数据，检索结果能回链到具体文档与章节，支撑上文的引用标注。
  • 复用：rag_retrieve 与 summarize_filing 两个 Agent 工具共用该链路；综合报告也调用它。
面试可讲：“RAG 不只是向量检索，检索质量（切片策略、重排、元数据过滤）与引用溯源同样关键”——本项目用本地 rerank + 元数据 boosting（向量库 Chroma 的 payload 过滤）拿到可用召回，且引用能回链到具体章节。

12 · 合规与护栏（投研场景刚需）

金融内容有强合规要求，ai/agent/compliance.py 在出口统一处理：

  • 禁用词改写：命中“买入/卖出/目标价/必涨/保本/无风险”等荐股与收益承诺词时，主动改写为中性投研表述（如“关注”“注意风险”），并标记 investment_view。
  • 免责声明：所有对外回答统一追加“AI 基于公开数据的投研观点，仅供参考，不构成投资建议”声明（attach_disclaimer，只追加一次）。
  • 护栏分层：Agent 出口（compliance）、分析器出口（attach_disclaimer）双保险；系统提示硬约束“禁止确定性收益承诺”。
为什么重要：LLM 在金融场景极易“越界给出买卖建议”，把合规做成可测试、可拦截、可改写的确定性层，是这类产品上线的前提。

可能被追问 & 应对

追问建议回答要点
为什么不用 LangChain/AutoGen？早期就自己实现轻量 ReAct，工具/护栏/置信度完全可控、零框架黑盒；核心是“白名单 + 结构化 Observation + 出口统一兜底”，框架只是壳。
怎么防止 LLM 编造数据？① 进推理前预取真实行情注入上下文；② 系统提示禁止凭记忆给数字；③ 护栏：声称缺数据却没调工具则强制回灌提示逼它取数；④ 结构化结果→人话改写。
RAG 召回怎么保证质量？段落切片 + 本地 rerank（相似度阈值过滤 + 文档类型/标题重叠 boosting）+ 元数据过滤（stock_code/section）；引用能回链到具体文档章节。
成本和时延怎么优化？模型路由：深度任务 M3、轻量任务 Flash；24h 响应缓存；置信度/引用/评分用确定性函数而非再调 LLM。
东财不可达怎么办？双源改造：财务改用新浪 stock_financial_abstract 建独立新表 finance_abstract，不动原 finance_statement/finance_core，所以已有因子计算不受影响；市值暂冻结。
回测安全吗？信号用受限 DSL（如 close > ma60），自然语言经 LLM 翻译成策略代码后在 AST 白名单沙箱执行，禁止任意代码。
